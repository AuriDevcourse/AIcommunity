## About This Session
A hands-on session about how each of us actually builds with AI day to day. Most of the time went to two themes: running models locally versus paying for cloud models, and showing real working setups. We compared local-model runners and hardware limits, walked through live project builds, and shared workflow tips for keeping AI projects organised and reasonably secure.

The recurring takeaway: local models are appealing (free, private) but need a strong GPU and still trail the paid cloud models on quality, so the practical answer is usually a mix, pick the cheapest tool that is good enough for the task.

## Topics
### Local models vs paid cloud
The central debate of the session. Running models locally through Ollama or LM Studio is free and private, but the group agreed it needs serious hardware and still trails the paid cloud models on quality. Justas recommended LM Studio because it shows which models actually fit your machine. Eividas reached for a stronger cloud model (Sonnet via OpenClaw) when a task needed real power. The shared conclusion was a pragmatic mix, use the cheapest tool that is good enough for the job rather than forcing everything local or everything cloud.

### Hardware and model size
A practical look at what it takes to run the bigger models. Frederik explained that a 32-billion-parameter model needs roughly 40 GB of memory at FP4/FP8 precision, which is why most laptops simply can't run the strong models locally. The group noted that different tasks lean on different hardware, image generation wants a capable GPU, while voice and transcription lean more on the CPU. Eividas summed up the trade-off: local models are free but slower and lower quality than the cloud options.

### Running local AI tools
How people actually run things on their own machines. Eividas walked through generating images locally with Flux / FLUX.2 [klein] on a home GPU, installed and managed through Pinokio (a one-click installer that pulls in missing dependencies) and ComfyUI for the node-based image workflow. Ollama and LM Studio came up again as the friendlier ways to download and serve local LLMs.

### Coding agents and IDE setups
The tools the group uses to write code with AI. Cline and Continue run as VS Code extensions, GitHub Copilot gives inline suggestions, and Claude Code was used to build whole projects end to end. Eividas advised sticking to Copilot or other verified plugins when wiring models into VS Code, rather than trusting unknown extensions.

### Live project builds
The hands-on demos. Auri live-built a small currency-converter web app with Claude Code, added Supabase plus Google sign-in so users never manage a password, and deployed it to Vercel, then toured the community dashboard with its forum and idea-voting. Yogi showed a business operations dashboard built with Claude that pulls in live data through several connected APIs, and mentioned using Whisper to clone his voice and Claude to draft offers and estimates.

### Workflow, security and staying organised
Tips for keeping AI projects tidy and safe. The group shared working in focused blocks with a Pomodoro timer, capturing notes and transcription in Notion, and double-checking every GitHub push so secrets don't leak by accident. Justas raised the trust question around granting Google auth access and pushing credentials to GitHub.

### Funding and monetisation
A short thread on keeping a community project sustainable. Auri weighed relying on one large backer against taking many smaller donations, leaning toward smaller contributions to stay independent.

## Tools & products discussed
- **Pinokio** — one-click "app store" that installs and runs local AI tools, pulls in missing dependencies automatically
- **ComfyUI** — node-based UI for local image generation
- **Ollama** — installs and serves LLMs locally
- **LM Studio** — friendlier local-model runner; shows which models fit your machine
- **Cline** — open-source coding agent that runs as a VS Code extension
- **Continue** — VS Code extension for using local models (Copilot-style)
- **GitHub Copilot** — inline code suggestions in VS Code
- **Claude / Claude Code** — Anthropic's models and CLI; used to build projects end to end
- **OpenClaw** — self-hosted personal AI assistant that runs on your own server
- **Qwen** — open local LLM; usable but slow on modest hardware
- **DeepSeek** — open reasoning model (older knowledge cutoff was a limitation)
- **GPT-5 Mini** — cheap cloud model, a step up from local options
- **Gemini** — Google's model; strong at image generation and keeping backgrounds consistent
- **Flux / FLUX.2 [klein]** — open-weight image-generation models that run locally on a strong GPU
- **Fooocus** — simplified image-generation UI (MidJourney-style)
- **Hugging Face** — hosts open models and offers pay-as-you-go inference for testing
- **Windsurf / Antigravity / Conductor** — IDE and agent front-ends for driving Claude
- **Vercel** — hosting and deploys for web projects
- **Railway** — hosting for servers and databases
- **Supabase** — auth and Postgres database
- **Base44** — AI app builder with brand/style presets
- **Mobbin** — searchable library of UI screenshots for design reference
- **Figma** — design-system reference
- **Opus Clip** — turns long videos into short clips
- **Fyxer** — AI email assistant that auto-drafts replies
- **Pomelli (Google Labs)** — generates brand mockups and campaigns from a website
- **Notion** — used for transcription and note capture
- **Claude Code skills (stop-slop, ui-ux-pro-max)** — remove AI "tells" from text; guide UI/UX work
